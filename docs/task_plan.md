## 关键问题
1. 设计提案与当前界面实现之间有哪些落差？（设计轨 D-1~D-5 已全部回答并落地）
2. 在保持轻量桌面工具定位的前提下，哪些功能最值得优先完成？（第 1–7 期本地核心已全部闭环）

## 已做决策
| 决策 | 理由 |
|------|------|
| 本轮仅研究与设计，不修改业务代码 | 用户明确要求先给方案（历史） |
| 第一轮实施聚焦数据底座、全局主题与今日学习首页 | 为各模块提供可复用基础（历史） |
| 使用项目内 `data/` 保存 SQLite 数据库 | 便于备份且不污染资料目录 |
| 单词笔记与重点标记复用 SQLite 数据层 | 词表重载后仍保留学习状态（历史） |
| **第 2 期：按 D2 方案 B 把 `word_states` 拆成 `words`（第一层）+ `word_notes`（第二层）** | 二层真相原则；解锁全局检索、生词本、Anki 导出 |
| **`word_key` 由 `korean␟meaning` 收敛为 `korean`** | D2 子决策：用户写笔记想的是"这个词"，不是它的某个释义 |
| **资料根目录改为"探测预填 + 落库配置"（D10-C）** | 原硬编码推导已失效，路径一移动就崩 |
| **schema 用版本号 + 迁移 + 迁移前强制备份（6.4）** | 已有真实用户数据，数据安全是底线 |
| **P5 联网分组不在第 2 期提供** | 属第 8 期；无开关框架先放空壳开关即假实现 |
| **第 3 期：过词的 `Space` 取 D14 的「揭示释义」，不取 4.2 正文的「下一个」** | 判断动作本身就跳下一个词，"下一个"这个键没有独立职责；而揭示释义决定第一遍标记的准确性 |
| **第 3 期：专攻不推进过词断点** | 第二遍是"攻"不是"过"；在专攻里改断点会把第一遍的进度搅乱 |
| **第 3 期：词表计数一律实时统计，不读存量列** | 同一个词可出现在多份词表并共享一行 `word_notes`，存量计数在多表间必然互相矛盾 |
| **第 3 期：重点标记（星标）保留为次级控件** | 三态答"会不会"、重点答"想不想再看一眼"，是两个轴；去掉唯一入口会让迁移保留下来的那批星标数据变成只读 |
| **第 6 期：碎片清单读 P3 的索引，这一页自己不扫目录** | 4.5 的边界条款点名原实现"每次进页面/每次启动都递归扫整个资料根"是已知缺陷；索引本来就是"哪些图片在哪儿、文件还在不在"的答案，再扫一遍是把同一份事实重算一次 |
| **第 6 期：`snippets` 整张进导出，尽管它含第一层列** | 两层混在一张表里，而导出是逐表 `SELECT *` 走的；丢掉 `title` 就是丢用户产出（6.5） |
| **第 6 期：`missing` 存进表，不逐行 `os.path.exists`** | 资料库图片抄 `materials.missing`，收集目录由 scandir 得出；一次刷新里绝大多数情况是"什么都没变" |
| **第 6 期：粘贴与导入都记作同一来源「收集」** | 两者落进同一个目录、之后的处理完全一致，而"怎么进来的"在文件落盘后重建不出来——写进库就是一条会失真的字段 |
| **第 6 期：P3 双击图片改为跳 P4** | 4.4 把 P4 列为图片的出口；外部看图工具一次只能开一张，而碎片页能扫一屏、还能记说明与标签 |
| **P3 右键删除走回收站，且只删第一层** | 原则 P6 说资料文件只读，这是唯一写明的例外；例外要站得住就得可撤销（回收站）+ 先问再做 + 标签与进度留在库里，文件还原后自动跟回来 |
| **第 3 期：色值在代码里也只有一个来源** | `QTableWidgetItem` 底色与图标色走不了 QSS；把这些值收进 `ui/theme.py` 常量，视图/组件/图标都不再写字面量 |
| **第 7 期：过词只在第一次过这个词时计数** | 5.4 的口径是「当日**新增**过词的词数」，而「新增」有精确判据——`previous_state is None`。它同时保证「今日过词」与同一页上的「已过 320 / 1400」变化量一致（后者的分子就是「状态非空」的词数）；来回重过同一个词不该把这个数刷上去 |
| **第 7 期：`Ctrl+Z` 把活动日志的计数也退回去** | 不退的话，同一页上的「已过」减了 1 而「今日过词」不动——5.4 明确要求口径统一，两个数当场打架。计数夹在 0 以上（跨零点撤销时那次减法落不到昨天那行） |
| **第 7 期：「今日亮点」与「今日已自动记录」条共用一次查询** | 卡取第一条、条排全部。同一份结果喂两处，两处的数就**不可能**对不上，而不是「应该不会对不上」 |
| **第 7 期：`today_activity()` 按类型合计，单位取 `MAX(unit)`** | `shadowing_minutes` 每次冲刷落一行，一天好几行，而 5.3 的条上要的是「跟读 24 分钟」一个数；`MAX` 顺手认领了老库里那条 `unit IS NULL` 的旧行（不去 UPDATE 它——只有整洁收益的数据迁移不做） |
| **第 7 期：「继续上次」的音频判据取 `listened_ms > 0`** | `playback_state` 在切曲那一刻就写，只看它的存在会让「仅仅点开看一眼」的曲目出现在「继续跟读」里；而 `position_ms` 可以回零（从头重听 / 冲刷时播放器还没有有效 source），「听过多久」只增不减 |
| **第 7 期：「今日已自动记录」条放主列，不按 H4 放进侧栏** | 5.3 给它的格式是**一行**，而侧栏只有 300px——硬塞进去必然折成三行，「一条」就不再是一条。以 5.3 的格式定位置（见 `PRODUCT_SPEC` 4.1 的 `〔v1.10 实施裁定〕`） |
| **第 7 期：「连续学习」的起点允许是昨天** | 5.4 的那个「或」字：早上打开工具时今天还没开始学，从今天起算会显示 `0 天`——而昨天明明学过。断的判据是「隔了一整天空着」 |
| **第 7 期：本期不额外加强调色** | D1 说两张新卡承接了 §6.1 的「一处温度」，本期按**内容**承接（纯事实的正向反馈），视觉上仍只有卡 2 那一处 `metricValueAccent` 与倒计时的 `accent-warm`。验收时若觉得右端两张卡该有自己的颜色，改这一条 |
| **D-5：单词仓过词/专攻改为居中实体卡片（`QFrame#vocabCard`）** | 周边用低对比度灰色展示词表名/序号/进度、`[词性]` 胶囊与 `💡 笔记与例句` 微卡，既提供上下文又不增加操作按钮干扰；专攻补上单步回退按钮与窗口级快捷键 `Qt.WindowShortcut` |
| **D-5：P2 录音在开录时锁定参考音轨，移除视频转换按钮** | 切换播放列表/音频不能污染正在录制或即将混音的参考音轨；混音失败自动降级保留纯人声录音；录音按 `{届数}届{起止题号}第{N}次.mp3` 命名 |
| **D-5：P4 修改标题同步重命名磁盘文件** | 调用 `database.relocate_file(old_path, new_path)` 原子更新磁盘文件名与全部 `_PATH_KEYED_TABLES` |
